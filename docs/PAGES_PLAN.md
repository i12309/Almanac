# GitHub Pages: следующий этап

## Текущее состояние

Публикация Pages не настроена в рамках подготовки макета. В репозитории нет
workflow автоматического развёртывания. Основной способ просмотра сейчас —
распаковать репозиторий и открыть `index.html`.

Подготовлена техническая основа для того же издания под HTTP: относительные пути,
навигация через `#`, заранее собранные данные и локальные ресурсы. Браузерная проверка
прошла с адресом вида `http://localhost:<port>/Almanac/index.html`.
Это проверка размещения в подпапке; фактического развёртывания на GitHub ещё не было.

## Предлагаемый вариант после согласования

Для небольшого статического альманаха можно начать с публикации ветки `main`
из корня `/`. Готовые `index.html`, `assets/`, `content/` и `read/` уже лежат в этом
дереве. Папка `docs/` в данном проекте предназначена для документации, а не для
сборки сайта.

GitHub поддерживает публикацию из ветки с источником в корне или в `/docs`, а также
отдельный workflow Actions. Основание:
[официальная документация по источнику публикации](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site),
проверена 6 октября 2026 года.

Окончательный выбор оставляем до обсуждения макета. Если понадобится отдельный
набор публикуемых файлов или дополнительная сборка на сервере, можно выбрать
workflow; это не должно менять автономную версию для скачивания.

## Что сделать при отдельной задаче на публикацию

1. Зафиксировать состав публичного издания и проверить, что в него не включён
   рабочий архив. Убедиться, что сгенерированные файлы актуальны.
2. Выбрать источник публикации и при необходимости добавить `.nojekyll` для
   раздачи готовой статики. Сейчас публикационные настройки не изменяются.
3. Настроить Pages выбранным способом и дождаться результата развёртывания.
4. Проверить фактический адрес из настроек GitHub: оглавление, прямую ссылку
   на главу, изображения, скачивания, лаборатории и `read/`.
5. Повторно открыть ZIP локально без сети, чтобы публикационные изменения
   не создали обязательной зависимости от хостинга.
6. Добавить подтверждённую ссылку на действующее издание в README.

Собственный домен, аналитика, сервисы аккаунтов и внешнее хранение материалов
не входят в текущий этап.
