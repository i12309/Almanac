# Вычисления в демонстрационных главах

Все три примера созданы для макета альманаха. Они **не извлечены из диплома,
диссертации или программ автора**, не воспроизводят результаты его работ и не
подменяют будущую проверку по архивным материалам.

`assets/js/labs.js` — самостоятельный скрипт без внешних зависимостей. В браузере
он создаёт `window.AlmanacLabs`, в Node.js доступен через `require()`. Функции
возвращают обычные объекты и числа, не изменяют DOM и не выполняют сетевых
запросов. Графики и элементы управления относятся к слою интерфейса.

## БЧХ: синдромы учебного кода

Использован двоичный примитивный БЧХ-код `(15, 7, 5)` над `GF(2⁴)`:

- Примитивный полином поля: `p(x) = x⁴ + x + 1`, число `0x13`.
- Порождающий полином: `g(x) = x⁸ + x⁷ + x⁶ + x⁴ + 1`, число `0x1d1`.
- Элемент `α` представлен числом `2`; `α⁴ = α + 1`.
- Бит числа с индексом `i` — коэффициент при `xⁱ`.
- При показе 15 бит старший, левый бит соответствует `x¹⁴`.
- Кодирование систематическое: старшие семь бит содержат сообщение, младшие
  восемь — остаток от деления `message(x) · x⁸` на `g(x)` над `GF(2)`.
- Синдромы: `Sⱼ = received(αʲ)` для `j = 1, 2, 3, 4`.

### API

| Вызов | Результат |
|---|---|
| `bch.encode(message)` | Число `0..32767`, кодовое слово для сообщения `0..127` |
| `bch.syndromes(word)` | Массив `[S1, S2, S3, S4]`; элементы `0..15` в полиномиальном представлении поля |
| `bch.fieldLabel(value)` | Строка `0`, `1`, `α` или `α^k` |
| `bch.errors(original, received)` | Расстояние Хэмминга между двумя 15-битными словами |
| `bch.multiply(a, b)` | Произведение элементов `0..15` в `GF(16)` |
| `bch.parameters` | Сериализуемый объект с параметрами учебного кода |

Все входы этих функций должны быть целыми числами в указанных границах.
Пример: `encode(1) = 0x1d1`, `syndromes(2) = [2, 4, 8, 3]`.

`errors()` знает исходное переданное слово и потому показывает истинное число
изменённых битов в эксперименте. В реальном приёмнике исходное слово неизвестно.

**В примере нет декодера и автоматического исправления.** Ненулевой синдром
показывает, что принятое слово не принадлежит коду. Нулевые синдромы означают
принадлежность коду, но не гарантируют совпадение с отправленным словом: например,
изменение пяти определённых битов может превратить одно кодовое слово в другое.
Параметр `t = 2` относится к исправляющей способности кода при использовании
соответствующего декодера и условия «не более двух ошибок».

При поступлении настоящего архива нужно отдельно установить его параметры поля,
порядок битов, полиномы и контрольные результаты; совпадение названия «БЧХ» не
означает тождества реализаций.

## Поезда: условное сравнение накопленных затрат

Это синтетический числовой пример для проверки ползунков, подписей и графиков.
Варианты А и Б не обозначают реальные поезда. Он не оценивает доходность,
экономическую эффективность или окупаемость реального проекта.

### Постоянные допущения

| Параметр | Вариант А | Вариант Б |
|---|---:|---:|
| Приобретение в момент `t = 0`, млн ₽ | 120 | 145 |
| Удельное потребление, кВт·ч/км | 4,7 | 3,8 |
| Обслуживание, млн ₽/год | 4,2 | 3,4 |

### Настраиваемые значения

| Поле | По умолчанию | Допустимый диапазон |
|---|---:|---:|
| `years`, полных лет | 20 | Целое число от 5 до 40 |
| `annualKm`, км/год | 250 000 | 50 000–400 000 |
| `energyPrice`, ₽/(кВт·ч) | 8 | 1–20 |
| `discountRate`, годовая доля | 0,05 | 0–0,2 |

Все расходы заданы в единой условной базе цен. Изменения цен, инфляция, остаточная
стоимость, налоги и выручка не моделируются. Ставка дисконтирования в этом примере
предполагается согласованной с базой цен. Дисконтирование ежегодных расходов
производится на конец года; приобретение относится к моменту `0`.

Годовые эксплуатационные расходы в миллионах рублей:

```text
annual = annualKm × energyKWhPerKm × energyPrice / 1 000 000
       + maintenanceMillionPerYear
```

Накопленная приведённая стоимость расходов по состоянию на год `Y`:

```text
C(Y) = acquisitionMillion + Σ[t=1..Y] annual / (1 + discountRate)^t
```

`trains.calculate(options)` возвращает:

```js
{
  series: [
    { id: 'train-a', name: 'Вариант А', values: [[0, 120], /* ... */] },
    { id: 'train-b', name: 'Вариант Б', values: [[0, 145], /* ... */] }
  ],
  totals: { a: /* C_A(Y) */, b: /* C_B(Y) */, saving: /* C_A(Y) - C_B(Y) */ },
  assumptions: { /* постоянные допущения, inputs, annualOperatingMillion */ }
}
```

Все денежные результаты, включая `totals.saving`, выражены в **миллионах рублей**.
Положительная разница `saving` означает меньшие суммарные приведённые расходы Б,
отрицательная — большие расходы Б. Точка пересечения кривых — равенство
накопленных приведённых затрат при заданных условиях, а не окупаемость проекта.

`trains.defaults` хранит начальные настройки. `trains.assumptions` содержит
постоянные параметры: `a`/`b` с полями `acquisitionMillion`, `energyKWhPerKm`,
`maintenanceMillionPerYear`, а также подписи единиц и допущений. Все эти объекты
сериализуются в JSON.

## Учебная модель: влияние двух параметров

Это самостоятельная иллюстрация изменения кривой, не модель из диссертации автора.

```text
y(x) = gain × (1 − exp(−x / tau))
```

- `tau` от 1 до 10; по умолчанию 4.
- `gain` от 0,5 до 2; по умолчанию 1.
- `x` от 0 до 20 с шагом 0,5: всего 41 точка.
- Обе оси — условные единицы; конкретная физическая величина им не присвоена.
- При `x = tau` значение достигает примерно 63,2% от `gain`.

`sensitivity.calculate(options)` возвращает `{series, assumptions}`. Единственная
серия имеет `id: 'response'`, `name: 'Учебная модель'` и массив `values: [[x,y],…]`.
Значения по умолчанию доступны в `sensitivity.defaults`.

## Проверка и правила дальнейшего переноса

Проверки запускаются без установки пакетов:

```sh
node --test tests/labs.test.cjs
```

Для БЧХ проверены известные векторы, полная таблица умножения поля, все 128
кодовых слов, минимальное расстояние и все 32 768 принятых слов. Условие нулевых
синдромов сопоставляется с независимым делением полиномов на массивах
коэффициентов. Проверена обнаруживаемость одно- и двухбитных ошибок и случай
изменения слова с сохранением нулевых синдромов.

Для затрат проверены нулевая ставка, дисконтирование на конец года и независимая
формула суммы аннуитета. Для кривой — начальная точка, значение на постоянной
времени, масштабирование и диапазоны. Для всех функций проверяется валидация;
обычное подключение скрипта в глобальный контекст также покрыто тестом.

В дальнейших главах нужно хранить рядом с реализацией вычислений:

1. Точные исходные данные и соглашения, включая единицы и округление.
2. Связь с архивным документом или исходной процедурой.
3. Контрольные входы, промежуточные величины и ожидаемые результаты.
4. Статус: проверено по оригиналу, восстановлено по описанию или учебный пример.
5. Отличия современного переноса и границы подтверждённого соответствия.

Тесты демонстрационных алгоритмов подтверждают только изложенные здесь модели;
они не являются свидетельством правильности ещё не изученных архивных работ.
