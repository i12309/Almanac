# Almanac: инструкции для агента

## Прочитать перед работой

1. `README.md` — запуск и текущее состояние.
2. `docs/CONCEPT.md` — замысел и границы проекта.
3. `docs/CONTENT_GUIDE.md` — модель материалов и порядок наполнения.
4. `docs/CODEX_SPEC.md` — этапы дальнейшей работы.

## Текущая стадия

Это демонстрационный каркас. Пользователь сначала проверяет интерфейс, навигацию,
графики, галерею, просмотр кода и эксперименты. Реальные архивы ещё не импортированы.
Публикация GitHub Pages отложена до отдельного решения пользователя.

## Технические условия

- Готовый `index.html` должен работать после распаковки репозитория через `file://`.
- Сайт также должен работать под HTTP в подпапке `/Almanac/`.
- Никаких обязательных серверов, API, аккаунтов, CDN и runtime-загрузки зависимостей.
- Classic scripts, относительные пути. `fetch()` для локальных данных, ES module imports,
  SPA history routes и service worker не являются основой автономной версии.
- Авторские данные — `content/works/*.json`; публичные вложения — `content/assets/`.
- `assets/js/content.generated.js` и `read/*.html` генерируются `tools/build.py`.
- У зрителя нет шага установки или сборки. Python/Node нужны только разработчику.
- Эксперименты — заранее написанные и проверенные функции из `assets/js/labs.js`.
  Код из архива показывается как текст. Не использовать `eval`, `new Function` или
  автоматическое выполнение загруженного кода.

## Сохранность и достоверность материалов

- Все текущие главы — demo, включая даты и исторические формулировки.
- Не приписывать автору вымышленные результаты, публикации, внедрения и воспоминания.
- Различать оригинал, редакторское объяснение, реконструкцию и учебный пример.
- Сохранять исходники без перезаписи; исправления оформлять как отдельные производные.
- Приватный входящий архив помещать вне публичной части проекта (например, в игнорируемый
  `inbox/`); переносить в `content/assets/` только выбранные для публикации материалы.
- Не переделывать согласованный дизайн при добавлении новой работы без задачи на дизайн.

## Проверка изменений

```sh
python3 tools/build.py --validate
python3 tools/build.py
python3 tools/build.py --check
node --test tests/*.test.cjs
```

При изменении взаимодействий выполнить `node tools/browser-smoke.cjs` с установленным
Playwright/Chromium; проверить локальную папку и HTTP-подпапку, ширину 360 и 1280 px.
Сведения о фактических проверках сохранять в `docs/VERIFICATION.md`.
Не активировать Pages и не публиковать реальные материалы в рамках одной лишь проверки.
